# Phase 9 Technical Sources

Access date for every source: **2026-08-25**.

Only official product documentation, standards, and upstream project documentation are used. No repository source, evidence, paths, or private implementation was uploaded.

| Area | Official source and version/status | Decision informed |
|---|---|---|
| Tauri single instance | [Tauri 2 Single Instance](https://v2.tauri.app/plugin/single-instance/), documentation updated 2025-11-03 | Register the plugin before every other plugin; a later launch focuses the existing window and delivers only validated local arguments. Linux sandbox limitations remain documented. |
| Tauri deep links | [Tauri 2 Deep Linking](https://v2.tauri.app/plugin/deep-linking/), current Tauri 2 docs | Accept only the statically configured `mellowyak` scheme and an allowlisted route grammar. Treat command-line URLs as untrusted. macOS registration is package-time only. |
| Tauri notifications | [Tauri 2 Notifications](https://v2.tauri.app/plugin/notification/), plugin 2.x | Request permission explicitly, retain in-app alerts, and use action/activation callbacks only where the platform API provides evidence. Do not claim a visual OS click when only the deterministic handler is tested. |
| Apple notification activation | [Apple UserNotifications: handling notification actions](https://developer.apple.com/documentation/usernotifications/handling-notifications-and-notification-related-actions), current Apple docs | Notification responses are processed through `UNUserNotificationCenterDelegate`; route data must be minimal, validated, and mapped back to an existing local entity before navigation. |
| Tauri tray | [Tauri 2 System Tray](https://v2.tauri.app/learn/system-tray/), Tauri 2 | Build native menus with `TrayIconBuilder`, update them from local state changes, and handle menu/tray events in Rust. No private paths or source content enters the native menu. |
| Tauri autostart | [Tauri 2 Autostart API](https://v2.tauri.app/reference/javascript/autostart/), plugin 2.x | Persist the preference in the engine and reconcile it with the OS plugin; unsigned development remains supported. |
| Tauri updater | [Tauri 2 Updater](https://v2.tauri.app/plugin/updater/), plugin 2.x | Signature verification is mandatory and cannot be disabled. Preserve the production public key, never commit a private key, use HTTPS in production, and permit loopback HTTP only in a separate disposable fixture. |
| Tauri capabilities | [Tauri 2 Capabilities](https://v2.tauri.app/security/capabilities/), Tauri 2 | Keep a single, narrow desktop capability and explicitly allow only required commands/plugins. Multiple overlapping capabilities would merge privilege boundaries. |
| Tauri CSP | [Tauri 2 Content Security Policy](https://v2.tauri.app/security/csp/), Tauri 2 | Keep `default-src 'self'`, prohibit remote scripts/assets, and allow connections only to IPC and loopback local engine origins. |
| Tauri distribution | [Tauri 2 Distribution](https://v2.tauri.app/distribute/), Tauri 2 | Build platform-native installers and keep version in the Tauri configuration synchronized with Cargo, frontend, engine, diagnostics, and updater fixtures. |
| macOS signing/notarization | [Apple Notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), current Apple notary service | A public build requires Developer ID signing, secure timestamp, Hardened Runtime, `notarytool`, successful service evidence, and stapling. The current unsigned package must remain labeled unnotarized. |
| Hardened Runtime | [Apple Hardened Runtime](https://developer.apple.com/documentation/Security/hardened-runtime), current Apple docs | Default to Hardened Runtime and add only necessary entitlements; never add broad exceptions speculatively. |
| Universal macOS | [Apple Building a universal macOS binary](https://developer.apple.com/documentation/apple-silicon/building-a-universal-macos-binary), Xcode 12.2+ | Every executable/framework/sidecar/browser component needs both `x86_64` and `arm64` slices before a package can be called universal. Intel runtime evidence does not verify Apple Silicon. |
| Windows notifications | [Microsoft local app notifications for desktop apps](https://learn.microsoft.com/en-us/windows/apps/design/shell/tiles-and-notifications/send-local-toast-desktop-cpp-wrl), current Microsoft Learn | Installed and unpackaged desktop apps have different identity/activation requirements; Windows notification activation remains workflow-configured until a Windows package is executed. |
| Windows signing | [Microsoft SignTool](https://learn.microsoft.com/en-us/windows/win32/seccrypto/signtool) and [Authenticode timestamping](https://learn.microsoft.com/en-us/windows/win32/seccrypto/time-stamping-authenticode-signatures), current Windows SDK guidance | Use Authenticode SHA-256 (`/fd SHA256`) with RFC 3161 SHA-256 timestamping (`/tr`, `/td SHA256`) and verify the produced installer; credentials stay in CI secrets. |
| Windows installers | [Tauri 2 Windows Installer](https://v2.tauri.app/distribute/windows-installer/), Tauri 2 | Build MSI on Windows and prefer native CI over cross-compilation; offline WebView2 policy must be explicit. Current macOS cannot runtime-verify Windows artifacts. |
| Linux notifications | [freedesktop.org Desktop Notifications Specification 1.3](https://specifications.freedesktop.org/notification/latest/) | Treat Linux notifications as asynchronous desktop-service messages; desktop environment behavior must be tested on Linux before claiming activation support. |
| Linux AppImage | [Tauri 2 AppImage](https://v2.tauri.app/distribute/appimage/) and [AppImage Packaging Guide](https://docs.appimage.org/packaging-guide/index.html) | Produce AppImage on the oldest supported base, include required runtime files and licenses, avoid hard-coded paths, and test the actual artifact on Linux. |
| GitHub build matrix | [GitHub Actions workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax), current GitHub Actions | Use an explicit OS/architecture matrix, `fail-fast: false`, immutable source commit, platform smoke tests, and per-artifact manifests. Workflow configuration is not a remote pass. |
| Artifact provenance | [GitHub artifact attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations), current GitHub Docs | Prepare least-privilege `id-token`, `contents`, and `attestations` permissions for public release provenance, but do not create or claim attestations during this no-push run. |
| Accessibility | [WCAG 2.2 focus order](https://www.w3.org/WAI/WCAG22/Understanding/focus-order.html) and [WCAG 2.2 reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow), W3C WCAG 2.2 | Preserve meaningful keyboard order, visible focus, no keyboard trap, and usable reflow/zoom. Test at 200% text zoom and keep LTR technical identifiers inside Hebrew RTL. |

## Version snapshot

The repository uses Tauri 2 and official plugin major version 2. Exact resolved Rust versions are pinned by `apps/desktop/src-tauri/Cargo.lock`; exact npm versions are pinned by `apps/desktop/package-lock.json`. The Technical Preview version is synchronized as `0.2.0-preview.1` only after every local configuration surface is updated together.
