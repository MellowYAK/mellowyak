# Phase 10 Product Truth Audit

Date: 2026-08-25
Baseline: `product/technical-preview-readiness` at `699add76f61d05cb38e86541a7a193b8f459a06b`

## Finding

The local engine already owns the important Phase 1–9 records. The principal Phase 10 gap is presentation: several delivery captures substitute a shared Technical Preview hero for operational state, while the real screens expose fragmented data without a daily-workflow hierarchy. Phase 10 will aggregate existing records; it will not invent project health or rebuild the snapshot, probe, regression, repair, Apply, or recovery engines.

## Architecture conclusion

- Reuse schema `0009_technical_preview_readiness`; no persistent Phase 10 domain field is currently justified.
- Add read-only aggregation endpoints only for Home, Project Overview, Activity/Episode detail, Regression Detail, and Diagnostics where joining existing entities in the browser would be error-prone or inefficient.
- Keep detailed source paths, hashes, reason codes, probe/evidence identifiers and raw manifests behind progressive disclosure and render technical tokens LTR in both languages.
- Use the existing event stream to invalidate bounded queries. No new polling loop is permitted.
- Deterministic screenshot state remains explicit test mode and must render the same production components; it may never target or mutate a registered real project.
